# Zoolanding Content Hub Notes

This repository owns the generic serverless content-hub BFF for draft-configurable article/content authoring workflows.

Durable decisions:

- The browser contract is same-origin `POST /features/content-hub/read` and `POST /features/content-hub/action`.
- Browser requests may carry only public draft, hub, source/action, article, taxonomy, asset, revision, schedule, locale, and safe form fields.
- Server-only policy, table names, bucket names, auth profile details, authorization decisions, signed URLs, tokens, credential refs, and raw secrets must never be returned to the browser.
- The BFF reuses auth-admin HttpOnly sessions by reading the shared auth-admin session/user-state DynamoDB tables. Mutations require the readable CSRF cookie to match the `X-ZLP-CSRF` header and the stored session CSRF hash.
- Authorization is action-scoped. Draft route `allowedGroups` are only UX hints; this Lambda must enforce roles server-side for every read/action.
- Article packages and published bundles are stored as S3 JSON files under deterministic `content-hubs/{environment}/{hubId}/...` prefixes. DynamoDB stores compact indexes, status, taxonomy, revision, schedule, asset, and moderation metadata.
- Initial public media URLs must be unsigned public URLs or draft-approved CDN URLs. Signed URLs are rejected from browser-facing payloads.
- Publish in this BFF creates validated published bundles and metadata. Propagating those bundles into Angular public `runtime.contentHubs.publicArticles` remains a separate runtime-read/front-door integration unless explicitly wired.
- 2026-06-22 21:52 CT: The first real content-hub BFF deploy is live in AWS `us-east-1` for `dev`, `test`, and `prod` as SAM stacks `zoolanding-content-hub-dev`, `zoolanding-content-hub-test`, and `zoolanding-content-hub-prod`. GitHub Actions environments `dev`, `test`, and `production` now hold the deploy configuration through environment vars plus `CONTENT_HUB_CONFIG_JSON_BASE64` as an environment secret; do not copy or log that secret value. The public repo `LynxPardelle/zoolanding-content-hub` has protected `dev`, `test`, and `main` branches requiring strict `guard` and `test` checks, admin enforcement, and no force-push/deletion. Vulnerability alerts and automated security fixes are enabled.
- 2026-06-22 22:48 CT: Cold-path optimization should keep read-only requests from creating unused AWS clients. `DynamoContentHubStore` creates S3 lazily only when object storage is used, caches DynamoDB table handles by table name, and `load_config()` caches the normalized public-safe profile config by raw config payload plus environment. This is performance-only; authorization, CSRF, and public-payload filtering remain unchanged.
- 2026-06-22 23:11 CT: The SAM template now defaults `FunctionMemorySize` to 512 MB so the content-hub Lambda has more CPU on the first AWS SDK/DynamoDB read path. Keep the parameter configurable per environment before considering provisioned concurrency, because provisioned concurrency adds a standing cost.
- 2026-06-23 01:14 CT: Blog MVP backend completion added protected `upsertTaxonomy`, `queueComment`, and `recordInteraction` actions plus richer article/publish metadata for SEO, category, tags, comment policy, content safety, canonical mode, and safe article path. Do not add unauthenticated public interaction writes to this protected BFF; use a separate public ingestion surface with abuse controls if visitor comments/reactions/forms become required.
- 2026-06-23 00:46 CT: Browser-facing action/read responses must not expose operational object keys such as `packageKey` or `publishedBundleKey`. `publicBundlePreview` may resolve the article's `latestRevisionId` when the draft omits `revisionId`, and `restoreRevision` must accept allowlisted IDs from action input as well as binding context. Draft-friendly aliases such as `articleCanonicalPolicy`, `articleContentSafetyPolicy`, comma-separated `articleTags`, and browser upload `dataBase64` are supported only after validation/normalization.
- 2026-06-26 18:40 CT: `articleDetail` is a protected read that returns the same public-safe article summary shape as `articleList` for one `articleId`. Use it to hydrate admin editors from metadata without exposing `packageKey`, `publishedBundleKey`, table names, bucket names, signed URLs, or server-only policy.
- 2026-06-28 01:22 CT: Content-hub authoring actions must accept draft-builder display labels for enum-like fields after server-side normalization, because generic dropdowns can submit localized labels such as `Listo para revisión`, `Públicos + moderación`, `Adaptable al sitio actual`, or `Avanzado libre`. The BFF maps only known labels/aliases into allowed canonical values and converts human category/tag text into safe slugs while preserving the label, so visual builders can accept terms like `algo más` without exposing raw ids or loosening authorization.
- 2026-06-28 02:25 CT: Article creation persists normalized product metadata instead of treating category/tags/path as draft-only form values. `createArticle` accepts public aliases such as `articleSlug`, `articleCategory`, `articleTags`, `articleVisibility`, and `articlePath`, strips accents for URL-safe slugs, deduplicates comma-separated tags, creates category/tag taxonomy rows, and stores `/blog/{categorySlug}/{articleSlug}` by default. `publish` should reuse the stored article path unless the caller provides an explicit safe path.
- 2026-06-28 04:42 CT: Missing `contentHub.action` must fail with an explicit browser-safe `contentHub.action is required` error instead of falling through to generic ID validation. `createArticle` remains valid without an incoming `articleId`; the BFF generates a safe article ID from timestamp plus slug after authorization and field normalization.
- 2026-06-28 05:43 CT: `publish` must mark the article metadata `visibility` as `public` when it writes the published bundle. Runtime-read intentionally serves only `status=published` plus `visibility=public` entries, so leaving a draft/review/private visibility after publish creates a false-success publish that cannot appear on public blog routes.
- 2026-06-29 01:44 CT: `contentHubs[].rolePolicies` is now the preferred authorization contract when present. The BFF checks exact action-scoped permissions for every protected read/action and uses legacy `roles.read/edit/publish/media/moderate` only as a compatibility fallback. Wildcard role-policy permissions are invalid and config failures return the generic browser-safe `Content hub config is invalid` message.
- 2026-06-29 02:06 CT: Editorial lifecycle now includes `approveArticle`, `unpublishArticle`, and `archiveArticle`. Unpublish/archive require publish-level permission, validate the article exists, set `visibility` to `private`, remove the public slug index, and keep immutable S3 bundles/revisions for audit instead of deleting history.
